Required implementation before running

The repository does not currently expose this as a supported command. Its production downstream pipeline intentionally accepts only a promoted 4TF export, and its existing diagnostic logistic probe uses fixture labels rather than the Trend Magic label.

Add one separate, research-only path. It must not relax or bypass production checks.

  1. Add a typed 3TF research config with a unique run identity and artifact root.
  2. Allow only the exact ordered intervals 1min,3min,15min in that research path.
  3. Embed from the pinned official checkpoint, not from a rejected matrix candidate.
  4. Reuse the existing causal label builder and purged walk-forward splitter.
  5. Run the raw baseline and frozen-embedding head on the identical folds and write both receipts.
  6. Keep the path unable to call promotion, trading deployment, or holdout evaluation.

Execution order after the research path exists

The command names below are stage contracts. Do not invent a CLI flag or route the experiment through the existing 4TF production command until the dedicated research command is implemented and tested.

# 1. Validate the new 3TF research config and source identities.
uv run mantis-v2 downstream-verify --config <3tf-research-config>

# 2. Build causal Trend Magic labels and split manifest.
uv run mantis-v2 downstream-prepare --config <3tf-research-config>

# 3. Freeze the official encoder and write resumable embedding shards.
uv run mantis-v2 downstream-embed --config <3tf-research-config>

# 4. Fit raw and embedding logistic heads on chronological folds.

# 5. Only after the gate passes, simulate. Never use this command to tune.
uv run mantis-v2 downstream-simulate --config <3tf-research-config>

Pass gate

Advance to a 3TF LoRA comparison only if embeddings beat raw features on validation and chronological test in all of the following:

  • Lower log loss and Brier score.
  • Lower calibration error without threshold leakage.
  • Stable improvement across more than one walk-forward fold.
  • Simulation improves after costs and Topstep risk rules, without using the reserved holdout for selection.

If the frozen probe fails, fix the label, execution assumptions, or feature construction before LoRA. RL for exits and sizing remains downstream of a proven entry signal and does not rescue a near-random classifier.

Resume and failure rules

  • Never delete matching partial embedding shards. Rehash and resume only the absent or invalid pair.
  • Never overwrite a run directory. Create a new run identity for changed config, data, code, or checkpoint identity.
  • Do not open the reserved holdout while choosing the head, threshold, or LoRA settings.
  • Stop immediately if source, config, corpus, or checkpoint provenance differs from the manifest.
