MantisV2 Official Pipeline Audit

Date: 2026-07-20. Scope: pinned official paper, source revision, and Hugging Face snapshot versus the local foundation, embedding, probe, and RL pipeline.

Conclusion. The current trading pipeline correctly consumes the pinned MantisV2 checkpoint and implements the essential 512-sample, channel-independent feature path. It is not a reproduction of official foundation pretraining, and it does not run the paper's strongest frozen-feature variants. Those are distinct gaps: pretraining matters to the repository's long-term foundation-model mission, while the frozen-feature variants are the most relevant next experiments for the currently rejected Trend Magic head.

Official sources

  • MantisV2 paper, arXiv 2602.17868.
  • Official source at commit 0c94f8c, including MantisV2 architecture, trainer, and pretraining example.
  • Hugging Face snapshot 99fe0f5; its config records length-agnostic 32 patches, last layer, CLS token, and pre_training=false.

Missed or deferred steps

PriorityOfficial stepLocal gap and impact
Mission-levelFoundation pretraining on synthetic CauKer2M using two RandomCropResize views, InfoNCE contrastive loss, projection head, AdamW, and cosine schedule.No local pretraining command, config, contrastive loss, augmentation pipeline, or CauKer2M reader exists. The official trainer documents these operations in trainer.py and the official README says CauKer2M produced MantisV2. This does not block using the pinned checkpoint, but it means the repository cannot yet build a MantisV2 foundation model from pretraining data.
Current downstreamPaper zero-shot recipe: transformer layer index 2 (third layer) plus combined CLS and mean token, yielding 512 dimensions per channel.The local schema supports it, but production uses final-layer CLS. The decision is explicitly deferred at docs/research/2026-07-19-mantisv2-supertrend-topstep-spec.md:66-78. Because the deployed encoder was NextLeg-fine-tuned using final CLS, this must be an isolated upstream-weight benchmark, not an in-place switch on existing embeddings.
Current downstreamSelf-ensemble across interpolation lengths 128, 256, 512, and 1024, plus the same set for the first-order difference.The local extractor uses only one 512 interpolation (mantis-v2/src/mantis_v2/embedding.py:153-170). The paper reports this as a test-time performance enhancement. It is optional, but consequential enough to benchmark after the intermediate-layer baseline; it multiplies embedding width and inference/storage cost.
Current downstreamOfficial classifier baselines: StandardScaler plus default logistic regression with max_iter=500, and retain Random Forest as a comparison.The local implementation has the right scaler/logistic structure but production changes class weights, C, and iteration limit (mantis-v2/configs/trend-magic-topstep-100k-head-c0001-v2.toml:49-62). There is no Random Forest path. Because the tuned logistic head failed its proper-score baseline, the official-default logistic and RF comparisons are useful controls, not production defaults.
Optional researchCross-model fusion, especially MantisV2 with TiViT-H or TiConvNext.Not implemented. The paper presents it as an additional performance strategy, not a requirement for MantisV2. It adds large models, new provenance, compute, and license review, so it should not precede the cheaper MantisV2-only ablations.

One local documentation inconsistency

docs/workflow.md:215-225 says production uses "Full encoder fine-tuning," while the committed production config selects transformer_finetune and the implementation freezes everything outside the transformer. The config and code agree with each other; the workflow wording is stale.

Recommended order

  1. Do not retrain the existing NextLeg model merely to imitate the paper. Its custom objective and preprocessing are deliberate.
  2. Create a separate, immutable official-weight feature experiment: layer 2 plus combined token, official-style 512 input, same purged Trend Magic folds.
  3. Compare against the current final-CLS embeddings using the official-default logistic control and Random Forest, while retaining the local proper-score gates.
  4. Only if that improves untouched walk-forward results, test the multi-length/difference self-ensemble.
  5. Track CauKer2M contrastive pretraining as a separate repository capability; it is not a prerequisite for the current Topstep pipeline.
